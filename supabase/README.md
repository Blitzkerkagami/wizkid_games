# WizKid Phase 4 cloud sync

This phase keeps SQLite as the game's source of truth and uploads pending rows to Supabase when a connection is available. No custom Node.js server is required.

## One-time Supabase setup

1. Create or open a Supabase project.
2. In **Authentication > Providers > Anonymous**, enable anonymous sign-ins.
3. In **SQL Editor**, run `schema/phase4_learning_sync.sql`.
4. Run `tests/phase4_security_checks.sql` and confirm its expected results.
5. In **Project Settings > API Keys**, copy the project URL and the `sb_publishable_...` key. Never put a secret or service-role key in Unity.
6. Edit `Assets/Resources/SupabaseConfig.json`, fill those two values, then set `enableSync` to `true`.

The first online launch creates an anonymous authenticated user. SQLite rows remain `pending` while offline or after failed requests. The sync service retries with exponential backoff and marks only the exact uploaded revision as `synced`.

## Phase 5A forecasting foundation

After Phase 4 is working, run `schema/phase5a_forecasting_foundation.sql` in the SQL Editor, followed by `tests/phase5a_security_checks.sql`.

Phase 5A adds:

- `learner_skill_features`: a security-invoker view that computes accuracy, response time, difficulty, recent-vs-previous trend, and data readiness per learner and skill;
- an initial minimum-data rule of 10 attempts across at least 2 sessions (raised to
  5 scored sessions by Phase 5D for ARIMA);
- `learner_forecasts`: protected forecast history that authenticated game clients can read but cannot write;
- `current_learner_forecasts`: the latest unexpired forecast per skill.

The future Python forecasting service will read eligible rows from `learner_skill_features` and write results to `learner_forecasts` using a server-only secret key. Never put that secret key in Unity.

## Phase 5B forecasting worker

Run `schema/phase5b_forecasting_worker.sql`, then
`tests/phase5b_worker_security_checks.sql`. The migration adds the unique source/model
key used for safe repeat runs.

The Python service lives in `../forecasting`. It uses a server-only `sb_secret_...`
key to read server-authorized forecasting data and upsert forecasts. Unity continues to use
only its publishable key and can read its own forecast through RLS; it cannot create
or alter forecasts.

## Phase 5C Unity forecast dashboard

Unity now reads `current_learner_forecasts` and `learner_skill_features` using the
anonymous user's access token and the publishable key. RLS continues to restrict both
views to the signed-in owner. Forecast and readiness rows are cached in the local
SQLite database (schema version 3), so the Adventure Map dashboard can display the
latest downloaded result while offline.

Enter Play Mode and open **AdventureMap**, then select **Learning Forecast**. The
dashboard shows expected score, mastery, confidence, trend, risk, recommended level,
and readiness progress. Use **WizKid > Phase 5 > Validate Forecast Integration** for a
local configuration/cache check.

## Phase 5D ARIMA forecasting

Run `schema/phase5d_arima_forecasting.sql`, followed by
`tests/phase5d_arima_security_checks.sql` and `tests/phase5d_arima_smoke.sql`.
This adds a server-only, security-invoker session-series view and changes forecast
eligibility to at least 10 attempts across at least 5 scored sessions. The Python
worker now stores `arima-session-v1` forecasts generated by Statsmodels ARIMA.

## Phase 6A end-to-end checkpoint

Phase 6A verifies the complete learning-data path before adding more gameplay or
forecasting features:

1. Enter Play Mode and complete enough gameplay for one skill: at least 10 attempts
   across at least 5 scored sessions.
2. Select **WizKid > Phase 6A > Request Cloud and Forecast Refresh** and wait for
   the local sync queue to become empty.
3. Run the protected backend `POST /forecast/run` with the server-only
   `FORECAST_JOB_TOKEN`, or wait for the next Vercel cron run. Never add that token
   to the Unity project.
4. Select **WizKid > Phase 6A > Request Cloud and Forecast Refresh** again, then
   select **WizKid > Phase 6A > Run End-to-End Forecast Check**.
5. A PASS confirms gameplay data reached SQLite and Supabase, an
   `arima-session-v1` forecast was downloaded, and the local sync queue is empty.
6. Select **WizKid > Phase 6A > Validate Offline Forecast Cache**, then repeat the
   final check on an Android device: turn on airplane mode, restart the app, and
   confirm that **AdventureMap > Learning Forecast** still displays the cached result.

The forecast card displays **Model: ARIMA**, making it clear that the visible result
comes from the Phase 5D forecasting worker rather than a placeholder calculation.

## Phase 6B Android quality testing

Phase 6B does not add another database migration. A development-only Android QA
overlay records SQLite availability, offline gameplay queuing, restart persistence,
cloud reconnect recovery, cached forecast access, app-update preservation, FPS, and
low-memory warnings. Build the initial and update APKs from **WizKid > Phase 6B** and
follow `Assets/Data/PHASE6B_ANDROID_QUALITY_TESTING.md` on a physical phone.

The Unity client continues to use only the publishable key. The quality report stores
device and test measurements but does not store Supabase secrets or the learner UUID.

## Phase 6C forecast validation report

Run `schema/phase6c_forecast_validation.sql`, followed by
`tests/phase6c_forecast_validation_security_checks.sql`. The new
`forecast_validation_details` view pairs every saved forecast with only the first
later scored session for the same learner and skill. This creates leakage-safe
predicted-vs-actual samples and also calculates a previous-score baseline.

Unity downloads only the signed-in learner's validation rows through RLS and caches
them in SQLite schema version 5. Open **Adventure Map > Learning Forecast > View
Forecast Accuracy** to see the child-friendly in-game report. It displays MAE, RMSE,
sample count, model version, baseline comparison, and a forecast-vs-actual chart.
There is intentionally no file export.

## Phase 6D UAT and ISO 25010 evaluation

Run `schema/phase6d_evaluation.sql`, followed by
`tests/phase6d_evaluation_security_checks.sql`. The Adventure Map now includes
an **Evaluate Game** flow for learner-assisted, parent, teacher, and IT evaluator
responses. UAT uses 20 indicators; the ISO/IEC 25010 instrument uses 28 indicators
across functional suitability, performance efficiency, compatibility, usability,
reliability, security, maintainability, and portability.

Responses are stored in SQLite schema version 6 before upload. The Unity client
can insert and read only responses belonging to its authenticated anonymous user;
it cannot update, delete, or read the cross-device aggregate. Researchers can run
`reports/phase6d_evaluation_report.sql` in the SQL Editor to obtain real response
counts, overall means, category means, and scale interpretations.

## Privacy and account notes

- Birthdays are deliberately not uploaded. The cloud profile contains the nickname, age, and selected wizard only.
- An anonymous account is device-bound. Clearing app data, uninstalling, or explicitly signing out can make it unrecoverable until a parent/teacher login is linked in a later phase.
- The prototype stores its refresh token in Unity PlayerPrefs. Before production distribution, move that token to Android Keystore/iOS Keychain storage.
- The backend owner is always derived from the authenticated JWT inside PostgreSQL. The client cannot choose another `owner_id`.
